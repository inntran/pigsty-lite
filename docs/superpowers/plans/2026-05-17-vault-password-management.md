# Vault-Backed Password Management Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Manage Patroni system passwords (and other secrets) through Ansible Vault — generate machine-to-machine passwords automatically, prompt for human-facing passwords, never store plaintext on disk. Tests bypass vault via plaintext overrides.

**Architecture:**

- `group_vars/all/vault.yml` holds every `vault_*_password` var, encrypted with `ansible-vault`. Gitignored. Generated by `./configure` on first run; respected as the source of truth on subsequent runs.
- Vault passphrase lives in `.pigsty/vault-pass` (mode 0600, also gitignored), referenced by `ansible.cfg`. Operator types the passphrase once at configure time; deploys are non-interactive.
- Role defaults reference `{{ vault_<name>_password | mandatory }}` (production path). Molecule scenarios override the *higher-precedence* alias var (`patroni_superuser_password: superuser-test-pw` already exists) and never touch the vault.
- A new Python module `bin/_vault.py` wraps the `ansible-vault` CLI for read/write of keyed entries. The `configure` script gains a `_ensure_vault()` step that runs after schema validation.

**Tech Stack:** Python 3 (stdlib + PyYAML), `ansible-vault` CLI, Bash for sanity tests, existing molecule scenarios for end-to-end verification.

```python
"""Thin wrapper around `ansible-vault` CLI for keyed secret storage.

The vault file is a YAML mapping of {key: value} encrypted as a single
ansible-vault blob. We never hold plaintext on disk; reads decrypt to
memory, writes encrypt from memory.
"""
from __future__ import annotations

import secrets
import string
import subprocess
import tempfile
from pathlib import Path
from typing import Any

import yaml

PASSWORD_ALPHABET = string.ascii_letters + string.digits


def generate_password(length: int = 24) -> str:
    """Cryptographically random alphanumeric password."""
    return "".join(secrets.choice(PASSWORD_ALPHABET) for _ in range(length))


def vault_exists(path: Path) -> bool:
    return Path(path).is_file()


def vault_read(path: Path, passphrase_file: Path) -> dict[str, Any]:
    """Decrypt path with the passphrase file and parse as YAML mapping."""
    result = subprocess.run(
        [
            "ansible-vault", "view",
            "--vault-password-file", str(passphrase_file),
            str(path),
        ],
        check=True,
        capture_output=True,
        text=True,
    )
    data = yaml.safe_load(result.stdout) or {}
    if not isinstance(data, dict):
        raise ValueError(f"vault contents at {path} must be a YAML mapping")
    return data


def vault_write(path: Path, data: dict[str, Any], passphrase_file: Path) -> None:
    """Encrypt data as YAML and write to path, overwriting if present."""
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)

    with tempfile.NamedTemporaryFile(
        mode="w", suffix=".yml", delete=False, dir=path.parent
    ) as tmp:
        yaml.safe_dump(data, tmp, sort_keys=True, default_flow_style=False)
        tmp_path = Path(tmp.name)

    try:
        subprocess.run(
            [
                "ansible-vault", "encrypt",
                "--vault-password-file", str(passphrase_file),
                "--output", str(path),
                str(tmp_path),
            ],
            check=True,
            capture_output=True,
            text=True,
        )
        path.chmod(0o600)
    finally:
        tmp_path.unlink(missing_ok=True)
```

```python
"""Orchestration for vault-backed password lifecycle.

Pure functions over a vault dict {key: value}. No file I/O; callers
combine this with bin._vault for persistence. Separating the policy
(which keys exist, machine-vs-human) from the I/O makes both pieces
trivially testable.
"""
from __future__ import annotations

from dataclasses import dataclass
from typing import Callable

from bin._vault import generate_password


@dataclass(frozen=True)
class Secret:
    key: str          # Variable name in vault.yml (e.g. vault_patroni_superuser_password)
    prompt: str       # Human-facing prompt label for interactive secrets
    length: int = 24  # Length for auto-generated secrets


MACHINE_SECRETS: tuple[Secret, ...] = (
    Secret("vault_patroni_superuser_password", "patroni superuser"),
    Secret("vault_patroni_replication_password", "patroni replication user"),
    Secret("vault_patroni_rewind_password", "patroni rewind user"),
    Secret("vault_haproxy_stats_password", "haproxy stats"),
)

HUMAN_SECRETS: tuple[Secret, ...] = (
    Secret("vault_grafana_admin_password", "Grafana admin web UI"),
)

ALL_SECRETS: tuple[Secret, ...] = MACHINE_SECRETS + HUMAN_SECRETS


def ensure_machine_secrets(vault: dict[str, str]) -> dict[str, str]:
    """Fill in any missing machine-secret keys with generated values."""
    result = dict(vault)
    for secret in MACHINE_SECRETS:
        if secret.key not in result or not result[secret.key]:
            result[secret.key] = generate_password(secret.length)
    return result


def ensure_human_secrets(
    vault: dict[str, str],
    prompter: Callable[[str], str],
) -> dict[str, str]:
    """Prompt for any missing human-secret keys; pass through existing ones."""
    result = dict(vault)
    for secret in HUMAN_SECRETS:
        if secret.key not in result or not result[secret.key]:
            result[secret.key] = prompter(secret.prompt)
    return result


def rotate(vault: dict[str, str], key: str) -> dict[str, str]:
    """Force-regenerate one secret. Raises ValueError for unknown keys."""
    secret = next((s for s in ALL_SECRETS if s.key == key), None)
    if secret is None:
        raise ValueError(f"unknown secret key: {key}")
    result = dict(vault)
    result[key] = generate_password(secret.length)
    return result
```

```python
def _prompt_passphrase() -> str:
    import getpass
    while True:
        first = getpass.getpass("Vault passphrase (min 8 chars): ")
        if len(first) < 8:
            print("Too short, try again.")
            continue
        second = getpass.getpass("Confirm: ")
        if first != second:
            print("Did not match, try again.")
            continue
        return first


def _ensure_vault_interactive() -> int:
    """Ensure passphrase file + vault file exist; fill in missing secrets."""
    if not VAULT_PASSPHRASE_PATH.exists():
        print(f"No vault passphrase found at {VAULT_PASSPHRASE_PATH}; creating one.")
        VAULT_PASSPHRASE_PATH.parent.mkdir(parents=True, exist_ok=True)
        VAULT_PASSPHRASE_PATH.write_text(_prompt_passphrase() + "\n")
        VAULT_PASSPHRASE_PATH.chmod(0o600)
        print(f"Wrote {VAULT_PASSPHRASE_PATH.relative_to(ROOT)} (back this up!)")

    if _vault.vault_exists(VAULT_PATH):
        existing = _vault.vault_read(VAULT_PATH, VAULT_PASSPHRASE_PATH)
    else:
        existing = {}

    import getpass
    updated = _passwords.ensure_machine_secrets(existing)
    updated = _passwords.ensure_human_secrets(
        updated,
        prompter=lambda label: getpass.getpass(f"Password for {label}: "),
    )
    if updated != existing:
        _vault.vault_write(VAULT_PATH, updated, VAULT_PASSPHRASE_PATH)
        print(f"Wrote {VAULT_PATH.relative_to(ROOT)} (encrypted)")
    else:
        print(f"Vault up to date at {VAULT_PATH.relative_to(ROOT)}")
    return 0


def _ensure_vault_silent() -> int:
    """In silent mode: refuse to prompt; require vault to already exist."""
    if not VAULT_PASSPHRASE_PATH.exists():
        print(
            f"ERROR: silent mode requires {VAULT_PASSPHRASE_PATH.relative_to(ROOT)} "
            "to exist (run interactive configure first to bootstrap the vault)",
            file=sys.stderr,
        )
        return 1
    if not _vault.vault_exists(VAULT_PATH):
        # Allowed: bootstrap an empty vault non-interactively by generating
        # only machine secrets. Human secrets are deferred until the next
        # interactive run.
        updated = _passwords.ensure_machine_secrets({})
        _vault.vault_write(VAULT_PATH, updated, VAULT_PASSPHRASE_PATH)
        print(f"Wrote {VAULT_PATH.relative_to(ROOT)} (machine secrets only)")
        return 0
    existing = _vault.vault_read(VAULT_PATH, VAULT_PASSPHRASE_PATH)
    updated = _passwords.ensure_machine_secrets(existing)
    if updated != existing:
        _vault.vault_write(VAULT_PATH, updated, VAULT_PASSPHRASE_PATH)
        print(f"Updated {VAULT_PATH.relative_to(ROOT)} (new machine secrets)")
    return 0
```

```python
    print(f"Rotated {args.rotate} in {VAULT_PATH.relative_to(ROOT)}")
    return 0
```

## Task 6: Document the secret model

**Files:**

- Create: `docs/secrets.md`

- [ ] **Step 1: Write the doc**

Create `docs/secrets.md`:

````markdown
# Secrets in pigsty-lite

pigsty-lite stores all sensitive values in an ansible-vault encrypted
file at `group_vars/all/vault.yml`. The vault passphrase lives in
`.pigsty/vault-pass` on the control node. Both paths are gitignored.

## Lifecycle

The `./configure` script bootstraps and maintains the vault:

| Run                            | Behavior                                                       |
|--------------------------------|----------------------------------------------------------------|
| First interactive run          | Prompts for a vault passphrase, generates machine secrets, prompts for human secrets, writes encrypted `vault.yml`. |
| Subsequent interactive runs    | Loads existing vault; adds only missing keys (idempotent).      |
| Silent run (`./configure -s`)  | Refuses to prompt. Bootstraps machine secrets only; errors if no passphrase file exists. Add `--no-vault` to skip entirely. |
| `./configure --rotate KEY`     | Force-regenerates one named key in the vault.                   |

## Secret categories

**Machine-to-machine** (generated automatically; never shown to operator):
- `vault_patroni_superuser_password` — Patroni's `postgres` superuser DSN
- `vault_patroni_replication_password` — `replicator` user used for streaming replication
- `vault_patroni_rewind_password` — `rewind_user` used by pg_rewind / leader-recovery checks
- `vault_haproxy_stats_password` — haproxy stats endpoint auth

**Human-facing** (prompted on first configure):
- `vault_grafana_admin_password` — Grafana admin web UI login

## Backup

`group_vars/all/vault.yml` and `.pigsty/vault-pass` are **not** in git.
Losing the passphrase is unrecoverable — back both up out of band
(password manager, encrypted USB, etc.).

If the vault file is lost but the passphrase is intact, re-running
`./configure` generates a fresh vault — but this rotates every secret,
which will break an existing running cluster. Plan accordingly.

## Test / CI behavior

Molecule scenarios provide plaintext values in `group_vars.all` of each
`molecule.yml`. Those values shadow the vault-backed defaults, so tests
never need a vault file. CI runs `./configure --no-vault` if it needs
the configure flow at all.

## Rotation example

To rotate the haproxy stats password:

```bash
./configure --rotate vault_haproxy_stats_password
make deploy
```

The next `make deploy` re-renders haproxy config with the new password.
````

## Self-review notes

**Spec coverage:**

- Machine secrets generated, never shown → Tasks 3+4 (`MACHINE_SECRETS`, no print after generation).
- Human secrets prompted, persisted → Tasks 3+4 (`HUMAN_SECRETS`, prompter wired to `getpass`).
- Test/CI fallback to static passwords → Task 5 step 3 + step 6 (molecule scenarios override the alias var).
- No plaintext on disk → Tasks 2+4 (write goes through `vault_write`; tempfile is deleted; passphrase file is the only plaintext, and it's gitignored).
- Both on-host runtime and vault as backup → vault.yml is source of truth at deploy time; renderered configs (patroni.yml, haproxy.cfg) carry the plaintext on each host with their existing 0600 perms. No additional code needed — Ansible already templates these.
- Documentation → Task 6.

**Open risk:**

- If `make lint` is strict about file paths under `group_vars/`, the rename in Task 1 could fire a new warning. Handled in Task 7 step 1.
- The vault file uses `sort_keys=True` so diffs are stable, but vault encryption is non-deterministic — every `vault_write` produces a different ciphertext even for unchanged plaintext. The "no changes" path in `_ensure_vault_*` skips the write to avoid touching the file unnecessarily.
