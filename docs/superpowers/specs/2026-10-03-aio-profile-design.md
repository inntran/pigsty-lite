# AIO (all-in-one) profile — design

Date: 2026-10-03
Status: approved in conversation, pending spec review

## Intent

A third reference profile, `aio`, that collapses the two SPOF hosts
(monitor/backup + PostgreSQL) onto one machine. It is a **temporary,
dev/demo** footprint: a laptop VM, a throwaway environment, or a stopgap
before a real SPOF/HA deployment. It is not hardened for production.

Success criteria:

- `profile: aio` with one `pg_primary` node validates, generates an
  inventory, and `make deploy` brings up PostgreSQL + Patroni + etcd +
  pgBouncer + monitoring + pgBackRest on that one host.
- Backups work out of the box to a local repo, and can additionally go to
  S3 by uncommenting a block in the response file.
- Converting to SPOF later is a response-file edit (`profile:` + add a
  monitor node), not a rebuild.

Decisions taken during brainstorming:

| Question | Decision |
| --- | --- |
| Purpose | Dev/demo, temporary. Backups uploaded to S3 when wanted. |
| Node declaration | Keep `role: pg_primary`; no new node role. |
| Patroni / etcd | Keep both (single-member etcd), as SPOF does. Patroni has no DCS-less mode and ~18 files outside its role assume it. |
| HAProxy / VIP | Off, as in SPOF. VIP is rejected by the schema. |
| Backup layout | Local repo1 + optional S3 repo2. S3 optional; the example ships a commented-out block. |
| Broken `backup:` wiring | Fix first, for all profiles. |

## Part 1 — wire the `backup:` response block to the pgBackRest role (all profiles)

**Problem.** `_generate_response_vars.py` flattens `backup.*` into
`backup_enabled`, `backup_schedule_*_oncalendar`, `backup_retention_full`
and `backup_secondary_store`, but no role or playbook consumes them. The
role reads `pgbackrest_retention_full`, `pgbackrest_schedule_full`,
`pgbackrest_schedule_diff` and `pgbackrest_s3_*`, all left at defaults.
`site.yml` imports `_pgbackrest.yml` unconditionally.

**Change.**

- `inventory/group_vars/all/main.yml` maps, with `default()` fallbacks to
  the current role defaults:
  - `pgbackrest_retention_full` ← `backup_retention_full`
  - `pgbackrest_schedule_full` ← `backup_schedule_full_oncalendar`
  - `pgbackrest_schedule_diff` ← `backup_schedule_differential_oncalendar`
  - `pgbackrest_s3_enabled` ← `backup_secondary_store.enabled`
  - `pgbackrest_s3_bucket` / `_endpoint` / `_region` / `_path` ←
    `backup_secondary_store.*` (region and path keep role defaults when absent)
  - `pgbackrest_s3_key` ← `vault_pgbackrest_s3_key`,
    `pgbackrest_s3_key_secret` ← `vault_pgbackrest_s3_key_secret`. Both
    are operator-supplied vault entries (like application passwords), not
    generated by `configure`. Referenced only when S3 is enabled.
- Schema: when `backup.secondary_store.enabled`, `type` must be `s3`
  (the only implemented backend). `region` and `path` optional strings.
- `site.yml`: the `_pgbackrest.yml` import gets
  `when: backup_enabled | default(true) | bool`.
  **Behaviour change:** a response file with `backup.enabled: false` no
  longer deploys pgBackRest. Nothing already deployed is removed.
- `_pgbackrest.yml` stays runnable directly (tag/standalone use) — the gate
  lives in `site.yml` only, matching the HAProxy gate.

## Part 2 — the `aio` profile

**Schema (`bin/_response_schema.py`).**

- `ALLOWED_PROFILES` gains `aio`.
- `aio` requires exactly one node in `nodes:`, with `role: pg_primary`.
  Any `monitor`, `backup_store` or `pg_replica` node is rejected with a
  message pointing at `spof`/`ha`.
- The existing "self_hosted requires exactly 1 monitor node" check is
  skipped for `aio` (the pg node is the monitor).
- `db_routing.vip_manager.enabled: true` is rejected for `aio`.

**Inventory (`bin/_generate_inventory.py`).** For `aio`, the single host
appears in:

- `postgres` (primary, seq 1) and `etcd` (seq 1) — unchanged logic;
- `backup_server` — via the existing "no monitor, no backup_store → primary"
  fallback, made explicit for `aio`;
- `monitor` — only when `monitoring.mode == self_hosted`. External modes
  leave `monitor` empty, exactly as today.

Host vars that differ per group (`postgres_role`, `postgres_seq`,
`etcd_seq`, `ansible_host`) must merge without conflict; the generator
already emits the same `ansible_host` in every group.

**configure CLI.**

- `-c/--profile` choices and the wizard prompt accept `aio`.
- For `aio`, the wizard skips the HAProxy/VIP prompts (VIP stays disabled).
- New `responses/aio.rsp.yml.example`: one `pg_primary` node,
  `backup.enabled: true`, and a commented-out `secondary_store` S3 block
  naming the two vault keys.

## Part 3 — pgBackRest `local` mode

**Problem.** `_pgbackrest.yml` runs the role as `client` on `postgres`
and then as `server` on `backup_server`. When one host is in both groups,
the server pass overwrites `/etc/pgbackrest/pgbackrest.conf` with a config
that points `pg1-host` at itself over TLS, which breaks `archive-push`.
This already affects SPOF/HA with external monitoring (backup_server
falls back to the primary).

**Change.**

- New `pgbackrest_mode: local`. Template renders:
  - `[global]`: log settings, `repo1-path`, `repo1-retention-full`,
    optional S3 `repo2-*` block, `archive-async=y`, `spool-path`.
  - `[stanza]`: `pg1-path`, `pg1-port`.
  - No `repo1-host*`, no `tls-server-*`.
- Role behaviour in `local` mode: install, config, stanza-create
  (`--no-online`, as server mode), timers. **No** TLS daemon and **no**
  8432 firewall rule.
- Mode is chosen from inventory, not from `cluster_profile`:
  - Play 1 (`hosts: postgres`): `pgbackrest_mode` = `local` when
    `inventory_hostname in groups['backup_server']`, else `client`.
  - Play 2 (`hosts: backup_server:!postgres`): `server`.
  - Play 3 (archive activation) unchanged; its
    `delegate_to: groups['backup_server'][0]` resolves to the same host.
- `local` mode asserts `groups['postgres'] | length == 1`. An HA cluster
  whose backup_server collapsed onto a pg node fails with an actionable
  message ("declare a backup_store or monitor node") instead of
  rendering a broken config.
- `pgbackrest_exporter` (monitoring_agents) reads the local config and
  needs no change; verify in testing.

## Part 4 — playbook gating

- `site.yml` HAProxy import: `cluster_profile not in ['spof', 'aio']`.
- `vmagent-scrape.yml.j2`: same condition for the HAProxy scrape job.
- Monitoring, Grafana and nginx plays already key off
  `groups['monitor'] | length > 0`; no change.
- Switchover, failover and scale playbooks get no AIO-specific guard
  (SPOF has none). Docs state they do not apply.
- Firewall rules sourced from the host's own address are harmless and
  left as is.

## Part 5 — tests and docs

**pytest (`tests/configure/`).**

- Schema: `aio` accepts one `pg_primary`; rejects 2 nodes, a monitor node,
  a backup_store node, a replica, VIP enabled; S3 `type` must be `s3`.
- Inventory: `aio` + self_hosted → host in all four groups; `aio` +
  external_push → `monitor` empty, other three present.
- Response vars / group_vars: backup block maps to `pgbackrest_*`.
- Template: rendered `pgbackrest.conf` in `local` mode has `repo1-path`
  and `pg1-path`, no `repo1-host` and no `tls-server-*`; S3 block appears
  only when enabled.
- CLI: `-c aio` accepted; fixture `aio.rsp.yml`.

**molecule.** New `tests/molecule/backup/molecule/local` scenario: one
host in `[etcd, postgres, backup_server]`, converging the real
`_pgbackrest.yml`; verify stanza exists, `pgbackrest check` passes, no
`pgbackrest.service` running, and a full backup completes.

**docs.**

- README: profile list gains `aio`.
- `responses/aio.rsp.yml.example` (Part 2).
- `docs/operations/firstrun.md`: short AIO section — temporary use only,
  local repo shares the host's disks unless S3 is enabled, Patroni/etcd
  retained for upgrade path, how to convert to SPOF.
- `roles/pgbackrest/README.md`: document `local` mode and the S3 vault keys.
- `docs/reference/ports.md`: note that 8432 is not opened in local mode.

## Out of scope

- Dropping Patroni/etcd for single-node deployments.
- S3 as the only repository.
- Guards on lifecycle playbooks for AIO.
- Uninstalling pgBackRest when `backup.enabled` flips to false.
- A worked `examples/aio/` bundle.
